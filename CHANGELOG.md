# Changelog

## 3.3.2

- **`--imports <file>` prints where each import resolved to.** One JSON array on stdout with an object per `import` line a run of the file reads: the file that declares it, the alias, the kind, the URL, ref and `path` as written, the full commit a git ref resolved to or the SHA-256 of the archive that was used, and `directory`, the absolute directory the alias stands for, so `<directory>/sv.api` is the file `cl/sv.api` includes. A tool that has to read an imported file itself gets the path from there and no longer needs to know how the cache is laid out. The walk is the one `--assert` makes: includes and imported files are followed to any depth, a line reached twice is listed once, and an alias nothing includes from is listed too. `stale` is `true` where a cached copy stood in for a remote that gave no answer. Nothing is sent, no `url` gate is checked, and `token_env` is never printed. `-r` prints one line, `-` reads stdin, a file without imports prints `[]`, and a file that can't be read is `error: …` with exit 1 and nothing on stdout. `--describe`, `--assert` and `--imports` each print a document of their own, and two of them on one command line are an error.
- **`set <name> [value]` in a `.api` file changes a setting for the requests below it.** An option on the command line applies to a whole run; a `set` line applies from where it is written to `set <name> off` or the end of the file. A setting is named as its long option is: `set export <external-id>` (`--export`), `set include-nulls` (`-i`), `set fail-fast` (`-f`), `set ndjson`, `set raw` (`-r`), `set stream` and `set timeout <seconds>`. So a file can say itself what it needs: a pull file asks for nulls and export, a file of `PUT /assert` lines for fail-fast, and each runs the same by hand as from a tool. `off` turns a setting off again and is the default for `timeout`; `on` may be written. A setting is the file's own: a file it includes, and a file of an import, runs with nothing set and the setting is back when the including file carries on, while a line in an included file ends with that file. An option on the command line holds for the whole run and no line turns it off or changes its value; the `-sa` log notes `↳ ignored: -i is set` under a line that asked for something else, and `--no-streaming` keeps `set stream` off. Only these seven are settings: where a request goes and as whom (`-b`, `-k`, `-c`…) is never a file's to set. A name that is no setting, a value it does not take or a `set` line in a `&&`/`||` chain stops the batch before anything is sent, so a file that needs a setting does not run without it. The preview and the log list the line. `api set include-nulls` on its own sends nothing and is an error. This takes the place of the `export <external-id>` / `export off` line, which was never in a release: write `set export <external-id>` / `set export off`.
- **At the prompt a `set` line changes what the session has set**, and `tab` completes the setting's name. The session stands where the command line stands for a batch: what it has set holds for every line typed after it and for a file run from the prompt, whose own `set` lines do not turn it off (`↳ ignored: the session has set include-nulls`). The last change wins, also over an option the session was started with: `api -i`, then `set include-nulls off`. A session started with `--export` no longer refuses a typed line with `export stays <name>`.
- **`ctrl+t` opens a settings menu at the prompt.** A row for each setting a `set` line can change: response streaming, export mode, include nulls, fail fast, NDJSON, raw JSON and the timeout, each with what the session has it at. `↑`/`↓` move the cursor, `enter` or the space bar changes the row it is on, and the menu stays open until `ctrl+t` or `esc`, so several can be changed in one visit. It takes the command area's place the way the `ctrl+h` shortcuts do, opens on its first row every time, and what was changed is said in its last row as the prompt's hint line says it. A row is a `set` line: changing it is typing `set include-nulls`, and what was typed or given at startup shows in the menu. The timeout, and the name for export mode the first time, are asked for in the command area as `ctrl+s` asks for a name; an answer that can't be used is refused with a notice and stays on the line to correct. **`ctrl+r` is gone** and `ctrl+t` no longer turns streaming on and off by itself: streaming is the menu's first row (`ctrl+t`, `enter`) and export its second.
- **`--install-syntax <editor>` installs syntax highlighting for `.api` files.** `sublime`, `vscode`, `cursor`, `rider`, `vim` or `nvim`. The grammars are in `editors/` and compiled into the client, so what is installed is the one for the syntax that client reads, and running the command again after an update is how the highlighting is updated. Each path written is a line on stdout, and nothing is sent. Sublime Text gets `API.sublime-syntax` in `Packages/User`, Vim and Neovim a package under their `pack` directory. VS Code and Cursor get a `.vsix` the client builds itself and hands to `code --install-extension` (`cursor …`); without that command on the `PATH` the file is written, the exit code is 1 and stderr says how to install it by hand. Rider, and any other JetBrains IDE, gets a TextMate bundle and one step in its settings, said on stderr. The Sublime syntax covers the whole of `AGENTS.md` and marks what would stop a batch; the TextMate grammar is a port of it that marks the same, and the Vim syntax colours what a line is. `tests/editors.rs` holds the Sublime syntax and the TextMate grammar to `editors/sample.api`, and the installs to a home directory of its own.
- **The hint line marks everything that is on**, one word each at its right: `nulls · fail-fast · ndjson · raw · timeout 45s`, and last, where it stood, `export` or `streaming`. A line too narrow for all of them drops the ones on the left first.
- **An export leaves a masked member out, and warns.** `--export` wrote `null` where the server answered a mask (`********`), and a `null` in a `PUT` body clears the member: an export sent back to the environment it was read from, which is what an export is for, emptied every secret it touched. The member is now not in the export at all, with `-i` too, so a write leaves a secret as it is on a record that exists and does not set it on one that is created. A list that held a masked value is left out whole; a response that is nothing but a mask is still `null`. The line on stderr is a warning and says so: `warning: response had masked data, left out at oauth2Clients/secret, localCredentials/password and 1 other place`, where it read `Response had masked data, now null at …`. It is printed under `-s` too, the run goes on and the exit code does not change. A batch that had such responses ends with one more line, also when it is stopped, so the warning is not lost in a long log: `warning: 2 responses had masked data left out of the export; read those members out with ~just or ~without`. A secret in an export is a sign that the read asked for too much. A masked identifier is still not one a record is found by.
- **`--export` with `-i` no longer drops a record's identity.** With `-i` an identifier a record does not have arrives as `"clientID": null`, and the export counted it as an identifier the record has: the key was removed and nothing was put in its place, so a record with only a key came out with no way to find it (seen on an OAuth2 client). A `null` identifier no longer counts, and neither does one that was masked; such a record keeps its key as `key?` and under the name. The `null` member stays in the output.
- **A confirmation nobody answered is no longer a yes.** `-p` (`Run? [Y/n]`) and the `confirm` directive read end of input as Enter, so wherever there was no terminal and nothing on stdin (CI, cron, an agent's shell, `</dev/null`, a closed or empty pipe, a program read from stdin with `-a -`) the question answered itself and every request was sent. Versions up to 3.3.1 did this, against what `AGENTS.md` said. End of input now sends nothing, prints `aborted (could not read confirmation)` and exits **1**; so does ctrl+D at a terminal. The exit code is 1 and not the 0 the documentation gave, so that a caller can tell "could not ask" from a person declining, which stays `aborted` with exit 0. An empty line (Enter), `y` and `yes` accept as before. Without a terminal the answer can be piped: `yes | api -spa file.api`, `echo n | api -spa file.api`. A `confirm` in a program that is itself read from stdin has nothing left to read an answer from, and without a terminal it stops the run. `tests/parity.rs` covers the preview for a file and for one request, `confirm` in a file and from stdin, each run in a session of its own (`setsid`) so the tests have no terminal wherever they are started.

- **`--timeout` is how long nothing may arrive, and the documentation says so.** The client waits that long for an answer and then for each further piece of its body, so a response that keeps arriving is read to its end: an export of twenty minutes is whole under the default of ten. That is what every release did; `AGENTS.md` read as if it were a limit on the whole transfer. `tests/parity.rs` now holds it, with a body that takes three seconds under a timeout of one, buffered, streamed and under a `set timeout` line, and `--timeout 0` and `set timeout off` against an answer that is late.
- **`--describe`, `--assert` and `--imports` no longer drop what stands beside them.** `api --describe a.api GET /people` and `api --assert a.api -sa seed.api` printed the document, exited 0 and said nothing of the request or the file to run. Both are now an error, as a request beside `-a` is: `--describe a.api prints a document and GET /people is a request: give one of the two`. `-r` beside one is still how it prints.
- **The settings menu fits a small terminal.** On a narrow one a label is cut and the value stays, so a row always ends in what the setting is at. On one too short for every row the blank rows go first and the settings then move with the cursor, with the row it is on and the menu's last row always in sight. A key of the menu between two `ctrl+c` takes the question back, as a key at the prompt does. In a session started with `--no-streaming` the streaming row and a typed `set stream` say that streaming stays off, and a file's `set stream` is logged as `↳ ignored: --no-streaming is set`. `api "set include-nulls # note"` is the error that `api set include-nulls` is.
- **Tests for what a review of `set` lines, the settings menu, `--imports` and the one HTTP client found unheld.** `tests/parity.rs`: the closing line of an export said once at every way a batch ends; a `set` line reaching no included, globbed or imported file; `set fail-fast` in all that `-f` does; `set raw`, `set ndjson`, `set include-nulls` and `set stream` in what is sent and asked for; `--assert` on a file with `set` lines; the lines of a batch on one connection, a request after a pause on a new one, and a redirect to another host without the credential; the menu under a resize, a paste and an unanswered dialog; `set stream` typed; a narrow hint row; and a file at the prompt that stops. `tests/imports.rs`: a listed checkout counts as used, a pinned archive is listed from the cache with no network, `stale` for an archive, a relative `dir` path, and no connection needed. A unit test that failed once in some twenty runs no longer shares a port with the test beside it.
- **The clipboard goes through `arboard`, in the place of `cli-clipboard`.** `cli-clipboard` has had no release since 0.4.0, and what it builds on (`block` on macOS, `wl-clipboard-rs` 0.7 on Linux) is code a coming Rust will refuse: every build said `the following packages contain code that will be rejected by a future version of Rust`. `> clipboard` and `ctrl+y` do what they did, on macOS, Linux (X11 and Wayland) and Windows. Under X11 what was copied is now handed to the desktop's clipboard manager when the client ends, so a one-shot `api GET /people > clipboard` can be pasted after it has exited where a manager runs; a session keeps hold of the clipboard for as long as it is open.
- **A certificate that is not trusted is reported as one.** A server with a self-signed, private, expired or misnamed certificate was reported as `Is COS running on <host>? 🤔`, the message for a host that does not answer. It now says `The certificate of <host> is not trusted: it is not signed by a public certificate authority.` (or that it has expired, is not valid yet, is for another host name, or has been revoked), and a port that answers without TLS says `No secure connection to <host>: …`. One-shot, in a batch and at the prompt. Nothing was sent over such a connection before and nothing is now.
- **`-f` prints the body when an `assert` or a `sleep while` could not be judged.** A 401/403/408/429/5xx on either ended the run with `… could not be evaluated, aborting` and no body, where a chain condition with the same answer printed it. Under `-f` the body now follows, last on stdout. A failed assertion (a "no") is still a verdict without a body, and without `-f` nothing changes.
- **A `> outfile` is shown behind the body in the preview and the `-sa` log**, as it is written and as the prompt logs it: `PUT /f {"y":2} > out.json`, where it read `PUT /f > out.json {"y":2}`.
- **A `.ndjson` outfile is NDJSON from the first write.** A response of one record (`GET /about > about.ndjson`, `GET /people/…~first >> people.ndjson`) is one line of NDJSON and one JSON value at once, and was written indented over many lines like JSON. A second `>>` then added a compact line under it, leaving a file that was neither. A `.ndjson` or `.njson` target now always gets one compact value per line: after `>`, after the first `>>` and after every later one, one-shot, in a batch and at the prompt. A list answered as JSON is written one element per line, and an empty list appended adds nothing where it added a blank line. Files already written are not touched.
- **More tests for what 3.3.0 to 3.3.2 added**, written against a line-coverage measurement (`cargo llvm-cov`) of the code added since 3.2.3. Confirmations: several questions in one run, ctrl+D, Enter and `n` at a real terminal in batch mode, a program on stdin answered from the terminal, stdin closed outright, and what the preview lists for chains and directives. Imports: a `.zip` and an uncompressed `.tar` run the fixture as the `.tar.gz` does, a truncated archive, a wrong `sha256`, a redirect loop, unsupported URLs, a clashing or repeated alias, JSON that is no import, `path` on a local repository and on an archive, and `-f` inside an imported file. `-f`: 408 and 429 end a run from a chain, an `assert` and a poll. `--export`: an `assert` and a `sleep while` judge what the server said, `> clipboard`, `>> file.ndjson`. The HTTP client after the move to reqwest 0.13 and rustls 0.23: every method with its body, a key as Basic and a token as Bearer, the OAuth2 exchange, and a certificate nobody signed refused with nothing sent over it. Colour at a terminal and none in captured output, which is what `IsTerminal` took over from `atty`. New dev-dependency: `rcgen`, for that certificate.
- **The request of an `assert` and of a `sleep while` is read as a plain line is.** A comment in its body was sent (`assert not POST /search {"q": 1 /* active only */}`), and so was a raw tab in a string. The server answers such a body `400`, and a 400 is a "no" to a check: the `assert not` passed, an `assert` failed on a body that was fine, a `sleep while` ended at its first poll and a `sleep while not` never ended. The `-sa` log showed the line without the comment. In a file, as an argument and at the prompt.
- **`>>` adds to a file that is not UTF-8, and to one that is no file.** The target was read as text before anything else. A CSV another program had saved as Latin-1 was refused with `Error writing to out.csv: stream did not contain valid UTF-8` and nothing was added; it now keeps its bytes and gets the rows behind them, in the shape its name asks for (no second header row in a `.csv`, one value per line in a `.ndjson`). `>> some.fifo` and `>> /dev/stdout` waited for ever, for a writer that was the client itself; they are written to as `>` writes to them.
- **An empty URI argument is not filled with the body.** `api PUT "$URI" '{"a":1}'` with the variable not set took `{"a":1}` for the URI and then waited on stdin for a body. It is `PUT needs a URI`, as `api PUT ""` was.
- **`import git` over ssh uses the ssh command git is configured with.** The client gives git an ssh that never stops to ask, in `GIT_SSH_COMMAND`, and git lets that variable win over `core.sshCommand`. Where that setting named a key or an agent's wrapper, an import failed with `Permission denied (publickey)` though `git fetch` worked. A `core.sshCommand` is now used as it is, like a `GIT_SSH_COMMAND` or `GIT_SSH` of your own.
- **`-c` beside `--1p` is an error.** The saved connection's token, or its OAuth2 client, went to the host 1Password named. `-c names a saved connection and --1p one in 1Password: give one of the two`.
- **A file named at the prompt runs as a file, however little it holds.** A `.api` file with exactly one request was taken for that request typed: the file's request took the place of the typed line, a body-less `PUT` in it opened the body editor where a batch sends it as it is, and what its describe block was warned for was not said. `one.api` now runs as `two.api` does.
- **A default connection that can't be used opens the picker.** At a terminal, plain `api` with a `default` that names no saved connection, or one with an `auth_type` or a URL that can't be used, printed its warning and ended with `no base URL specified`: the session could only be opened with `-c` or after the file was mended by hand. "No saved connection is used" now means what it means with no default: the picker opens. A batch is unchanged.
- **Shift+Tab behind a key Tab has just completed writes nothing.** Under `-x`, `"gdprForgotten":` followed by Shift+Tab wrote `false`: the last of a list of values that Tab had not gone into. Shift+Tab goes back in the list Tab is going through, values and `@type` subtypes included, and starts none.
- **`ctrl+y` copies the request as it was sent.** The curl command took `;skipNulls=false`, the NDJSON types and `;stream=true` from the settings at the moment of the keypress. After a file with `set include-nulls` had ended, or a row of the `ctrl+t` menu was changed, the command was not the request. The settings are now kept with the request.
- **A ghost is shown for a `~map(` name typed in another case.** `GET /x~map(COM` showed no ghost and Tab wrote `~map(com.heads.csv)`. The ghost now shows the rest, as it does behind `@file~map(`.
- **The connection form offers `.app.heads.com` only behind a name.** Tab on `cos.example.com` or `myhost:8080` in the URL field made it `cos.example.com.app.heads.com`. A host with a domain of its own, a port or a path gets nothing.
- **A connection added with `ctrl+q` loads behind its form.** The session stood still, form on screen and keys unread, until the server had answered, and what was typed meanwhile landed in the prompt. The form now keeps its spinner (`loading...`) and reads the keys away, as the form a session starts with does, and a server that refuses the load is named in the hint line.
- **The splash's top row is as wide as its box for any version.** With a version of seven characters (`v3.3.10`) the row would have been a column wider than the box, and wrapped in a terminal of 36 columns. A version that has no room is left out.
- **The form the picker empties into is an empty one.** Deleting the last saved connection opens the form for a new one, and it opened with what an earlier visit to the form had left typed in it: the URL, the method and the credential.
- **Tests for what the 2026-11-18 review of the whole client found unheld.** `tests/parity.rs`: a program on stdin that is not UTF-8, for a run and for each document; a streamed response on stdout and a chain judged under `--stream`, without a CommerceOS; `-m` for a file named as an argument; an include that is not text, a glob that is none and an `import … @file` that is not UTF-8; no replaced-bytes warning for a `-sa` line without an outfile; the `ctrl+o to open file` hint and its absence after a write that failed; `-c` with a connection that can't be used, at a terminal; a server that announces a spec and has none. `tests/imports.rs`: a fetch that fails after the lookup answered leaves no checkout and sends nothing. Unit tests: the two shapes of a store error that were not held, and an append with no free name for a partial file.
- **A `#` in a URI is sent.** `DELETE /people/com.x.id=A#1` was sent as `DELETE /people/com.x.id=A`, and `GET /a~where(n="x #y")` arrived cut off at the `#`: a URL parser reads a `#` as the start of a fragment, and a fragment is never sent. So a write could reach another record than the one its line names. A `#` the line reader leaves in a URI (no blank in front of it, or inside a quoted value or the parentheses of an operator) is now part of the URI and is sent as `%23`, in a file, as an argument, at the prompt and in the curl command `ctrl+y` copies. A ` #` with a blank in front is a comment, as before.
- **A write is not turned into a `GET` by a redirect.** A `POST`, `PUT`, `PATCH` or `DELETE` answered with a `301`, a `302` or a `303` was sent on as a `GET` without its body, and the `200` of that `GET` was logged under the write, which had not been done. Such a redirect is now the answer: its status is printed, a chain reads it as a "no", and `-f` stops at it (`-f` now stops at any 3xx that arrives as an answer). A `GET` and a `HEAD` are sent on as before, and a `307` or a `308` sends any request on as it is.
- **A request that is read whole does not ask for a stream.** Under `--stream` every request asked the server to stream, also a `>> file`, a `> clipboard`, an `assert` and a `sleep while` poll, whose answers are read whole. A streamed answer has its status before its body, so an error can arrive inside a `200`, where a `>>` would add it to the file and an `assert` take it for a yes. Those four no longer carry `;stream=true`.
- **`--ndjson` with a glob of JSON files asks for NDJSON.** `PUT /x @parts/*.json` asked for `application/json` back whatever the run had set. The files are still sent as one JSON array, and what is asked for is what the run asked for.
- **`@export[1].json` is the file of that name.** A name with `[`, `?` or `*` was always read as a glob, so a file called that was `no files match`, or another file was sent in its place. A file that has exactly the name is now the body; with no such file the name is a glob as before.
- **A file body that can't be read is not said to be missing.** `PUT /x @folder` and a file without read permission said `File not found`. They now say `could not read folder: …` with the reason.
- **The OAuth2 token exchange follows no redirect.** The client secret is in the body of that request, and a `307` from the token endpoint would have carried it to wherever the answer pointed.
- **A warning about the data stays with its request at the prompt.** That masked data was left out of an export, or that bytes were replaced with U+FFFD, was said in the hint line only. In a file, a pasted block or a chain the next request took the hint line within the moment, so an export of several files could leave secrets out without a word. There it is now also a `↳` note under the status line of the request it is about. One request alone says it in the hint line, as before.
- **A line taller than the terminal no longer pushes its answer away.** After a request whose line took more rows than the terminal has (a pasted body of a hundred lines), as many blank rows as the line had were printed under the answer, and the status line stood off screen above them. Room is made for the rows the line is shown on.
- **Enter under `-x` reads no bracket in a comment.** In a body of several lines, Enter behind a comment that held more closing brackets than the body had open (`"a": 1 // }}`) ended the client with a panic. A bracket in a comment is none now, the line's indent goes by what stands before its comment, and a body on one line that holds a comment is not laid out anew, which broke the comment at its first comma.
- **Down in the connection picker stops at the last match of a search.** While a search was typed, Down moved on to the row the search line stands on, with no row marked, and Enter there opened the form for a new connection in the place of connecting to the match.
- **`ctrl+y` says why it copied nothing.** Before any request, and where the clipboard could not be written, the key did nothing and said nothing. It now says `no request to copy yet` or `could not copy to the clipboard: …`.
- **The connection picker keeps to a short terminal.** With more saved connections than the terminal has rows the picker printed them all, the screen scrolled, and every key and every frame of the spinner drew the list once more under the last. It now shows the connections that fit, moved along with the selected one, with a `⋯` on the first or the last row where the list goes on. A search is cut the same way, and a taller window shows more.
- **A window resized while a connection is tried is drawn at its new size.** A resize that arrived while the picker or the form waited for a server was dropped: the picker went on at the old width, and so did the prompt behind it until the next resize.
- **Tab and the ghost read a URI as the line reader does.** A blank in a quoted value or in the parentheses of an operator ended the URI for completion: behind `GET /people~where(name="James Bond")` nothing was offered and Tab did nothing, and under `-x` the ghost of a body's brackets was shown inside a value that was still being typed, where Tab wrote them. The URI now ends where a request's URI ends, and nothing is offered inside a value that is open.
- **Tab writes what the ghost shows in four more places.** `GET /x~map(ÄR` showed no ghost and Tab wrote the name: a name is now matched in any case of any alphabet by both. Tab on a URI kept neither blanks in front of the line nor more than one blank behind the method. Tab in the middle of a file path replaced what stood behind the cursor with a completion of the whole word, with no ghost: it writes nothing there, as in the middle of a URI. And a body file in front of an outfile (`PUT /x @da > out.json`) could not be completed at all: the path the cursor is in is the one that is completed, with its ghost.
- **A git command that has ended is not waited for.** The client read a git command's output until every process holding the pipe had ended, so an ssh connection that stays open for the next one (`ControlPersist`), or a credential helper that lingers, held an `import git` up for as long as it lived, past the five minutes a git command is given. What the command wrote is taken when it ends.
- **A pattern that the directory above matches is refused in an imported file.** `.*` and `.?` match `..`, so an include like `.*/.*/**/*.api` in an imported file had the client walk the directories above the import, a whole disk with enough of them, before the include was refused for leading out. Nothing outside was read or sent. Such a pattern is now refused by what it says, in an include and in an `@file` body.
- **Tests for what the third review of the whole client found unheld.** `-f` in a chain at the prompt (the last request stops the block, a "no" that was asked for does not), esc and ctrl+c during the request of an `assert` and the poll of a `sleep while`, a server that goes away in the middle of a session, `ctrl+s` in a session on OAuth2 client credentials (the client is saved, not its token), deleting the default connection, a check whose body is not closed on its line, the request under the cursor past an escaped quote, and a spec whose types go round in circles.
- **Each stream is coloured by what it is itself.** A `-sa` log sent to a file or a pipe from a terminal (`api -sfa seed.api > run.log`, `out=$(api -sfa seed.api)`) was written with escape codes in it whenever stderr was still the terminal, so the `└─HTTP/1.1 …` line a tool is told to look for was not there as written. Stdout is now coloured when stdout is a terminal and stderr when stderr is one. `NO_COLOR` was not followed at a terminal for a request or a batch, and is.
- **An include of an imported file with a `..` behind a `**` is refused by what it says.** `a/**/**/b/../../../**/*.api` read as a place inside the import, since each `..` took back one `**`, and was then walked as written: a `**` stands for no directory too, so the walk went above the import and from there through the disk, while the file was read and before `-p` showed anything. No file outside was ever read, each match was refused afterwards. The line is now `include leaves the import: …` before anything is looked up, and an `@file` pattern of that shape is refused the same way.
- **`api -m file.api` prints the block where `-ma` does.** For a file named as a one-shot argument the describe block was printed before the file's imports were fetched and its `url` gate checked, so a run that stopped at one of those had still said what it was about to run. `tests/parity.rs` now holds that for `-m`, `-ma` and `-sma`, and which of `LC_ALL`, `LC_MESSAGES` and `LANG` picks the text.
- **A paste into an open value of a URI is that value.** With `GET /companies~where(name="` on the line, pasting `Head Office"` left `HEAD Office"`: the paste started with the name of a method, was taken for a request line and took the place of what was typed. The same for a value that starts with `put`, `set`, `url`, `sleep`, `#` or the name of a `.api` file. Behind a quote or a parenthesis of the URI that is still open, a paste now goes in where the cursor is, whatever it starts with.
- **A paste promotes `GET` to `PUT` for what promotes when typed.** Pasting `~count` or any other text behind `GET /people ` made the line a `PUT` with that text as its body. Only a JSON value and an `@file` do, as when they are typed.
- **The body editor keeps to a short terminal.** On one of seven rows (or eight, where the prompt took two) the editor was a row taller than the screen, which then scrolled at every key and left a ruler in the scrollback each time. It now shows as many rows of the body as there is room for, down to one, and its header and prompt are cut to a row each where they would not fit. On a terminal of six rows or fewer the host written into the splash when a connection has loaded went over another line of the box; it is left out where its line is no longer on the screen.
- **Under `-x`, a body shows what Tab writes.** Tab completed a key or a value in a body in places where no ghost said so: behind `[{`, on a word typed without its quote (`{na`), on a value (`"status": `, `"gdprForgotten": fa`), and on a key in its quotes after the cursor had moved. The ghost now shows the first of what Tab offers wherever Tab writes, and nothing where Tab writes nothing. A `[` in a file name (`@export[1`) was taken for the start of a body by the ghost, which showed a `]` where Tab completes the file; the file path comes first for both. An enum the spec has as strings (`"enum": ["1", "2"]`) is written with its quotes, where it was written as a number.
- **Tab keeps a second slash, and a server without a spec keeps `/about`.** On `GET /people//` Tab wrote a completion without one of the slashes, with no ghost. Once a server had answered `404` for its spec, the `about` the ghost had shown behind `GET /` was gone and Tab did nothing, without a word. Tab between the two characters of a `&&` in front of a request with an outfile subtracted below zero (a panic in a debug build, nothing in a release). Unit tests now hold completion with text of other alphabets in front of the cursor.
- **`>>` to a `.csv` drops only a header row that is the file's.** The first line of what was added was dropped whatever it was: rows answered under another header (another `~map`) landed under columns they were not of, and an answer that was no CSV at all lost its first line. The first line is now dropped when it is the target's header row. Anything else is added whole, with `warning: the first line of the response is not the header row of rows.csv: it was appended too` on stderr, in the hint line at the prompt.
- **`>>` adds to the array behind a byte order mark.** A `.json` target saved with a mark in front (PowerShell, some Windows editors) was not read as JSON, and the answer was added under it as text: two documents in one file. The mark stays in front and the array behind it is added to. The header row of a `.csv` behind a mark is the header row too.
- **A streamed answer behind a byte order mark, and a number too small for a double, are judged as what they are.** Under `--stream`, `0` behind a mark was truthy to a chain where the same answer buffered was falsy. `1e-400` was falsy, since a double rounds it to zero: zero is now told by a number's digits.
- **A base URL with a user or a password in it is refused.** `-b https://svc:secret@host` sent two `Authorization` headers, the one made from the URL and the client's own, and printed the password at the top of every log; written without a scheme it went over plain `http`. It is `error: invalid value for -b: a base URL holds no user or password (user@host)`, without the value repeated, and a saved connection with such a URL is not used. A saved URL that names no host is said to be that (`its URL names no host`), where a request got `no base URL specified` for a connection it had named.
- **An empty method is not a `GET`, and an empty `-b` beside `-c` is no base URL.** `api "$METHOD" /people/x '{…}'` with the variable not set sent a `GET` with the body. `api -c conn -b "$URL" GET /x` with the variable not set asked an OAuth2 connection's token of a host that was none; it ends with `no base URL specified`, as without `-c`. A body that is a negative number (`api PUT /balance -5`) is a body, and an argument that is not UTF-8 is said to be that, where it was `unexpected option --help`.
- **Tests for what the fifth whole-app review found unheld, and two small things beside them.** `tests/parity.rs`: a `sleep while` waits its interval between checks and five seconds without one (nothing failed when the wait was taken out), and ctrl+o says `could not open <file>` for a file that is gone. `tests/editors.rs`: every pattern of the TextMate grammar compiles, where the grammar was held only through its snapshot. The Vim syntax reads a file from its start (`syn sync fromstart`), so a jump into the middle of a long body no longer colours its lines as lines of their own. `AGENTS.md` says that a redirect takes the `Authorization` along only to the same scheme, host and port. New dev-dependency: `fancy-regex`, the engine `syntect` already brought.
- **A request is read as what it is: a body is no URI, and a bracket in a URI no body.** Found by the sixth whole-app review. `PUT {"a":1}`, with the URI forgotten, was sent to a path made of the body (`PUT /api/v1/%7B…`); it is `PUT needs a URI` now, in a file, as arguments and at the prompt. `GET /people/com.x.id=[A#1]` was refused as an unclosed body, and in a file took the lines under it along: a bracket in the middle of a word opened a body, in which `#` and `//` start a comment. Such a bracket is the URI's now. A `url` line with `&&` or `||` in its trailing comment (`url has localhost:5000 # dev && test`) no longer puts the describe block under it out of place. `--assert` reads an `@file` body as the bytes a run sends: it stripped comments the run did not, and listed assertions the server would refuse. `api -m "my seed.api"` prints the block of a file with a blank in its name.
- **A base URL with a `?` or a `#` in it is refused.** `-b 'https://cos.example.com/#/orders'`, as copied from a browser, was taken as it stood, and every request's path was put behind it: each `GET`, `PUT` and `DELETE` went to `/` with its body and its credential, and a `200` from the page there passed for an answer. It is `error: invalid value for -b: a base URL holds no `?` or `#`` now, exit 1 with nothing sent, and a saved connection with such a URL is not used. Beside it: a password in a base URL whose scheme is not written whole (`http:/svc:secret@host`) is no longer repeated in the error, a default connection whose URL names no host is said to be that under `-k` too, a token endpoint that answers with an empty `access_token` gave no token, and a keychain that can't be opened at all (a container without one) is `could not read the keychain: …` where it was a panic.
- **An empty answer appended to a `.csv` is not warned about, and a certificate that is refused is an answer.** `GET /x >> rows.csv` answered with an empty body said `warning: the first line of the response is not the header row of rows.csv: it was appended too`, with nothing appended. An unpinned `import archive` whose host answered with a certificate the client does not accept counted as a remote that gave no answer, and the copy in the cache ran in its place under `cached copy: remote unreachable`: it stops the batch with `could not reach import …` now, as a certificate problem does for `import git`.

## 3.3.1

- **`-f` / `--fail-fast` stops at the first failed request.** A plain request that answered 4xx or 5xx never stopped a batch, and the run still exited 0. With `-f` the first response of 400 or above ends the run with exit 1, nothing after it is sent, and its body is written to stdout as the server sent it, last, in `-sa` mode too (where bodies are otherwise not printed). That is what lets a tool pick up a failed `PUT /assert`: a 409 `failed assertion` whose `failures` say what didn't hold. A request asked as a question is left alone: a chain segment with another after it (`GET /x || PUT /x {…}`), `assert not`, and a `sleep while` poll may be answered "no". A status that is never an answer (401/403/408/429/5xx) ends the run from anywhere. An error is not written to a `> outfile`. It works for one request (`api -f PUT /assert '{…}'` exits 1 where it otherwise exits 0), for a program line and from stdin; at the prompt, `api -f` stops a pasted block or a file at the failing request with `stopped at 409 (--fail-fast)` and keeps the session. The `assert` keyword is unchanged. Mind that a passing `/assert` answers `200` with `null`, which is falsy to `&&`/`||` and to the `assert` keyword: put `PUT /assert` on a line of its own.
- **`--export <external-id>` rewrites responses as seed data.** `api --export com.heads.seedID GET /users > users.json` prints a response that can be `PUT` back where it was read or to another environment, any number of times, and find or create the same records. In every object, however deep, `identifiers.key` is removed. A record that has another identifier is found by that one. A record with none keeps its key under the name you give and as `key?`, the key that may name nothing, which the API takes to name the record where one has that key and reads as not written where none has. `identifiers` moves to the front of its object, behind `@type`; other members keep the server's order. It applies to 2xx JSON and NDJSON bodies wherever they go (stdout, `> file`, `>> file`, the clipboard), for one request, in a batch and at the prompt. An error body, a body that is not JSON and every request body are left alone, chains and asserts judge what the server answered, and `--stream` is ignored while it is on. This is what the `mingle` script did as a second step over saved files, built in, with no `jq`. Writing an export that holds a `key?` needs a server that knows it.
- **A masked value in an export becomes `null`, and the client says where**: `Response had masked data, now null at oauth2Clients/secret, localCredentials/password and 1 other place`. A path runs from the top of the response and leaves out positions in lists, so it is one place however many records had it; two are named and the rest counted. On stderr for one-shot and batch runs, in the hint line at the prompt.
- **The export name is a namespaced key**, by the server's own rule: three dot-separated segments of letters, digits and `_`, with `-` allowed in the second and third and `$` in the third, at most 128 characters. Anything else is an error before a request is sent, which also catches a forgotten name (`api --export GET /users`).
- **`ctrl+r` turns export mode on and off at the prompt**, the way `ctrl+t` does streaming, and `export` shows at the right of the hint line while it is on, in the place of the `streaming` marker. The first time, it asks for the name in the command area: there is no default. A name that is not a namespaced key is refused with the prompt's regular notice, and the dialog stays open with the name there to correct until it is given one or left with `esc`. The name is remembered for the session; one started with `--export <name>` has it already. Listed under `ctrl+h`.
- **`ctrl+c` while a name is asked for ends the session cleanly.** In the `ctrl+s` save dialog (and the new `ctrl+r` one) it exited from inside the input, leaving the command area's top ruler in the shell, an unused session's splash with it, and bracketed paste and the keyboard protocol switched on. It now ends the way `ctrl+c` twice at the prompt does.
- **A branch is looked up again for every line at the prompt.** An imported ref was resolved once per process, so an interactive session kept the commit a branch had when it was first imported. Typing the `import` line again now picks up a push. A batch still asks the remote once per run, so every file in it sees the same commit.
- **The import cache cleans up after itself.** Using a checkout or an unpacked archive marks it used, and a run that fetches something new removes the ones unused for more than 30 days, along with what interrupted fetches left behind. A branch that moves every day no longer leaves a copy per commit in `~/.cache/api/imports`. A pruned commit is fetched again when it is next asked for.
- **`path` on an import says where the alias starts, not where the import ends**, and `AGENTS.md` now says so: a file under `path` may include or send a file elsewhere in the same repository or archive.
- **`tests/imports.rs` covers nested imports and more of what an imported file may hold**: repositories that import repositories three levels deep, a gate two imports down, two that import each other, one that imports another commit of itself, and fixture files for directives, chains, every kind of body, an outfile and a failing assert, each run as a directory, a git repository and an archive. Remote tests import the fixture from this repository at tag `3.3.0`. `tests/parity.rs` can now read where text landed on the screen (`pty::rows`, a prompt of a chosen width), and checks the name dialog row by row at four widths.
- Two tests in `tests/cli.rs`, `url_with_operators_succeeds` and `url_with_negation_operator_succeeds`, fail against a current server: it refuses `~where(active=true)` on `/echo-all` with `400 field not found`, where it used to answer 200. The client is not the cause; they are left failing until the server's answer is settled.

## 3.3.0

- **`import` brings `.api` files in from somewhere else.** `import git cl { "url": "https://github.com/Polyjuice/cloddy", "ref": "2.1.0" }` fetches a repository and makes its files includable under the alias, as if `cl` were a directory next to the file: `cl/sv.api`, `cl/seeds/*.api`. There are three kinds, used the same way once declared, so a batch can swap one `import` line for another and keep its includes. `import git` takes a `url` (`https://`, `ssh://`, `git@host:path`, `file://`) and a `ref` that is a tag, a branch, or a full commit SHA, and fetches with the `git` on the `PATH` and your own git credentials, never stopping to ask for a password. `import dir cl { "path": "../cloddy" }` uses a local directory where it is, nothing fetched or cached, which is the kind to point at a working copy while writing files others will import. `import archive cl { "url": "https://…/cloddy-2.1.0.tar.gz" }` downloads a `.tar.gz`, `.tar` or `.zip` (told apart by content) and needs no `git`; a tarball packed under one top directory, the way releases are, starts inside it. `git` and `archive` take an optional `path` for a subdirectory. The JSON may be written inline, over several lines with comments like a request body, or come from a file: `import git cl @cloddy.json`, read exactly like a request's `@file` body, so relative to the working directory.
- **Imports are resolved before anything runs**, while the file is read: ahead of the `url` gate, the `-p` preview and the first request. A bad URL, a missing ref, a wrong hash or a failed login stops the batch with exit 1 and nothing sent. The `-sa` log and the `-p` preview say what was used, one line per import: `import cl https://github.com/Polyjuice/cloddy 2.1.0 (a1b2c3d)` for git, `import cl https://…/cloddy.tar.gz (sha256 9f2c1ab)` for an archive, the directory for `dir`. A branch is looked up again on every run, so that commit is how you know what a run used; pin a tag or a SHA when the batch must be repeatable.
- **An archive can be pinned and can carry its own token.** With `"sha256": "…"` a download whose hash differs is an error, and once the archive is in the cache a run needs neither network nor token. Without it the URL is treated like a branch and downloaded on every run. `"token_env": "ARTIFACT_TOKEN"` names an environment variable whose value is sent as a bearer token, so the secret stays out of the file; it goes to the archive's host only, the client's API key is never sent there, and a missing variable is an error. Archive URLs are `https://` or `file://`, with plain `http://` accepted for `localhost` and `127.0.0.1` only, and a redirect is followed only to `https://`.
- **Fetched imports are cached by content** in `~/.cache/api/imports` (`API_IMPORT_CACHE` overrides it), keyed by commit or by SHA-256. A commit SHA already there needs no network; a tag or a branch costs one `git ls-remote` and is fetched only when it points at a new commit. When the remote can't be reached, the copy a tag, a branch or an unpinned archive URL last resolved to is used, and the log line says `cached copy: remote unreachable`; outside `-sa` that is a warning on stderr.
- **An import can't reach outside itself or widen where a batch runs.** An imported file's includes and `@file` bodies resolve relative to that file, and one that points outside the import (`@/etc/hosts`, `@~/…`, `../../x.api`) is an error before anything is sent. Symlinks in a repository are checked out as plain files, and an archive unpacks files and directories only: links are skipped, an entry named outside the archive is an error, and so is anything over 1 GB. The `url` lines of an import form a gate of their own that must pass as well as the batch's, so an import can refuse an environment but never add one to your allowlist. A `> outfile` in an imported file is not restricted; read an import with `-p` before running it the first time.
- **An alias belongs to the file that declares it**, from that line down. An included file doesn't see its parent's aliases and declares its own, and an imported file may import too. Declaring an alias twice in one file is an error, and so is an alias that names a real file or directory next to the `.api` file, since `cl/sv.api` could then mean either. An import that leads back to a file already being read is reported as `include loop detected`.
- **Imports work at the prompt and as one-shot arguments**, like the other directives. At the prompt an alias lasts for the session, so `cl/sv.api` runs on a later line, and `tab` completes the alias and the files inside it.
- **Closing a prompt that was never used clears its splash.** Leaving only cleared the input area, so a session opened and closed without sending anything left the splash box in the shell. Once a request has been logged the splash stays in the scrollback as before.
- **`tests/imports.rs`** runs one fixture tree, `tests/fixtures/import`, as a directory, a git repository and an archive against a recording server and expects the same requests from each. Three of its tests fetch this repository from GitHub at tag `3.2.2`, over https, over ssh and as a release tarball; `API_TEST_OFFLINE=1` skips them. It needs no CommerceOS: `cargo test --test imports`.
- New dependencies for `import archive`, all pure Rust: `sha2`, `flate2`, `tar`, `zip`.

## 3.2.0

- **One grammar in a `.api` file, as one-shot arguments, and at the prompt.** A line now means the same request wherever it is written, because all three are read by the file parser. Directives and includes work outside files: `api assert /companies/x` exits 1 unless truthy, `api sleep 5 while not /x~count` polls, `api seed.api` is `api -a seed.api`, and `api "GET /a && PUT /b {…}"` chains (quote the `&&` for the shell). At the prompt, `confirm` asks in the hint line (`y`/enter, `n`/esc), `sleep` and `sleep while` show a spinner and stop on esc, `assert` logs its status line without the body, `url` checks the current connection, and `seed.api` runs the file with each request logged as if typed; a stopped program leaves the session open. ## 3.1.4

- **`assert` pre-checks in `.api` batch files**: `assert GET /companies/com.heads.seedID=ourcompany` runs the request once and stops the batch, exit 1, unless the answer is truthy; `assert not GET /people~where(givenName=Test)~count` demands the opposite. It runs in file order, so it works as a pre-flight check at the top or as a verification after a write. Truthiness is the same rule as `&&`/`||` and `sleep while`, and the condition takes the same shape: a single-line request (implied `GET`, inline body allowed), no chain, no `> outfile`. The status line prints as for any request, but the body never does — an assert is a verdict, not data, so it can't leak into a batch's stdout. A failure names its reason: the status for a non-2xx (`error: assertion failed: assert GET /companies/x (404 Not Found)`) or the falsy body for a 2xx (`(0)`, `(null)`), compacted and capped at 80 characters. A 401/403, 5xx, or timeout aborts the same way. Mind that `[]` is truthy: assert a `~count` or a single item, not a list.

## 3.1.3

- **`sleep while` polling in `.api` batch files**: `sleep 20 while GET /imports~where(state=running)~count` re-runs the request every 20 seconds for as long as it's truthy, then moves on to the next line; `sleep while not GET /people~count` waits for the opposite, until the answer becomes truthy. Built for phasing a batch around asynchronous server work — kick off an import, wait for it to land, then read it back. The interval is optional (default 5s) and takes the same forms as plain `sleep` (`20`, `2s`, `500ms`, `1.5`); the first check happens immediately. Truthiness is the `&&`/`||` rule: `false`, `null`, `0`, `""`, and non-auth non-2xx statuses like 404 are falsy, everything else on a 2xx is truthy — so poll a `~count` or a scalar, never a list, because `[]` is truthy and would loop forever. The condition can be any single-line request (leading `/` implies `GET`, inline bodies allowed) but not a chain and not a `> outfile`; those are rejected when the file is parsed. Polls print nothing at all in plain `-a` mode. In `-sa` mode the loop logs one dimmed line when it starts and one when it finishes (`↳ waited 1m40s (5 checks)`), so a long pause in the log is explained and a stalled one shows what it's waiting on. There is no maximum wait; ctrl+c stops the run. A 401/403, 5xx, 408/429, or timeout while polling aborts the whole batch with exit 1 and the offending status line, exactly as in a chain — retrying an unanswerable question forever would hide an expired token or a broken server. `-p` preview lists each poll as `sleep 20s while not GET /…`. Documented with the other directives in a new `AGENTS.md` §6.

## 3.1.2

- **The response body now sits directly under the status line**, instead of being separated from it by a blank line. The body still has one blank line below it, so consecutive requests stay visually separated and blocks concatenate exactly as before. Applies to the TUI, non-interactive runs, and bulk mode alike; a `> outfile` note takes the body's place under the status line as it always did.
- **Body auto-expansion now follows the endpoint's schema.** The `[` prepended on a PUT/PATCH to an array endpoint is driven by what the loaded OpenAPI spec says that endpoint carries: an array of objects expands only on `{`, an array of scalars on any JSON value start, and anything else — including a URI with no spec loaded — not at all. Previously every character except a short blocklist expanded, so a mistyped `>` turned `PUT /suppliers <` into `PUT /suppliers [<`, costing two backspaces to undo, and `"` or a digit could expand into an element shape the endpoint could never accept. Pasting follows the same rule: a scalar pasted onto an array-of-objects endpoint is no longer wrapped. The `[{ ` body ghost and the expansion now share one shape resolver, so the hint and the expansion cannot disagree.
- **`GET` → `PUT` promotion requires a body start.** Typing at the body position promotes the method only when the character could actually begin a body — `{`, `[`, `"`, a number (`-` or a digit), `true`/`false`/`null`, or `@` for a file reference. Previously anything not explicitly blocklisted promoted, so `/suppliers <` became `PUT /suppliers <`.

## 3.1.0

- **Breaking: `-t` is now `--stream`, not `--token`.** Bearer tokens are long-form only: `api --token YOUR_TOKEN`. The short flag moved because streaming had none, and `-t` is the natural letter for it — it also makes bundles like `-str` (silent + stream + raw) work. An old `api -t <token> GET /people` no longer sends the token; a JWT left in the method slot is detected and reported (`-t is now --stream. Use --token <TOKEN> for a bearer token.`) rather than sent as a nonsense method. The detection is deliberately narrow — three dot-separated segments, over 40 characters, no slashes — so no real method or path can trip it, which also means an **opaque** (non-JWT) token passed to `-t` is not caught. Update scripts to `--token`.
- **Response streaming**: with `--stream` the body is written out as it arrives instead of being read into memory and pretty-printed first, which is what large exports and `~map(...)` transformations want. Off unless asked for, via `--stream` or `API_STREAMING` (`1`, `true`, `yes`, or `on`, any case); `--no-streaming` overrides both, so a single run can opt out without unsetting the variable. It's requested as a `;stream=true` media-type parameter on `Accept` and `Content-Type`, which a server that doesn't stream simply ignores. Where the bytes go: `> file` and piped stdout stream, as does stdout with `-r`; a terminal without `-r` still buffers and pretty-prints; `>> file` and `> clipboard` buffer because both need the whole body; and **any non-2xx buffers**, so an error page never streams into an outfile. Streamed stdout is byte-for-byte identical to the buffered path, trailing newline included.
- **Streaming keeps `&&`/`||` chains working** without holding the body: the leading 4KB is retained and judged exactly as a full read would be. Every falsy payload (`false`, `null`, `0`, `""`) is a handful of bytes, so anything that overflows the prefix can only be truthy — a streamed segment decides a chain identically to a buffered one, and `streaming still writes an outfile for a chain` is covered by the test suite.
- **`ctrl+t` toggles streaming in interactive mode**, with a `streaming` marker at the bottom right while it's on. It's gated on the server actually advertising the `response:streaming` feature flag in `/about` — otherwise the toggle declines with `streaming not available on this server` instead of silently doing nothing. While streaming is active, `ctrl+h` grows a section spelling out the caveats, linking to `<base-uri>/api-docs#description/streaming`.
- **Two streaming caveats worth knowing** (also in the README and `AGENTS.md`): a streamed `> file.json` is **not** pretty-printed — the file holds the server's bytes verbatim, so parse it rather than eyeballing it, or drop `--stream`; and a streaming response commits to its status line before the body is generated, so **a `200` can still carry an error inside the payload**. Check the content, not just the status.
- **A key or token without `-b` now uses the default connection's URL.** Previously `--key`/`--token` suppressed saved-connection loading entirely, leaving no base URI at all — supplying credentials shouldn't discard the saved host. Only the URL is taken; the credential from the command line wins, and an OAuth2 default connection no longer performs a token exchange whose result would be thrown away. A 401 in this case reports the error rather than reopening the connection picker, since the credential came from the command line.
- **A missing base URL says so**: `Error: no base URL specified. Use -b <url> or -c <connection>.` on the non-interactive and bulk paths, which previously fell through to a request against a bare path and asked whether COS was running on the empty string (`Is COS running on ? 🤔`). That message is now reserved for genuine connection failures, as intended since 3.0.6.
- Fixed `-s` emitting a trailing blank line. The blank after the body is the bottom margin of the status envelope — the counterpart to the one printed under `HTTP/1.1 200 OK` — but it was gated only on output being a terminal, not on silent, so `-s` dropped the header and its separator and kept the trailing gap. It goes to stderr, which is why redirecting to a file never showed it. Silent output now ends at the body's own newline, in all three shapes (streamed, raw, pretty).

## 3.0.6

- **`&&` request chaining**: `GET /people/123 && PUT /people/123 { "name": "Joe" }` runs the PUT only when the GET was truthy. Works in the TUI and in `.api` bulk files — the main use is conditioning a write on a read. Truthiness follows JavaScript: `false`, `null`, `0`, and `""` are falsy; `[]`, `{}`, and everything else on a 2xx are truthy — so `GET /people~where(givenName=X)~count && DELETE /people~where(givenName=X)` skips the delete when the count is 0. A non-2xx status is a plain "no" (404 → falsy, chain stops quietly), but auth failures (401/403), 5xx, 408/429, and timeouts are errors: they abort the whole run (exit 1 in bulk) instead of silently skipping the write. Skipped segments are reported (`↳ skipped 1 request`). `-p` preview lists every segment with its marker; `&&` inside a JSON string or body is never a separator; multi-line bodies work in any segment.
- **`||` chaining**: runs the next request only when the previous was falsy — `GET /people/123 || PUT /people/123 {…}` creates the person only if missing. Mixed chains evaluate left-to-right like a shell (a skipped segment doesn't change the outcome), so `GET /x && PUT /x {…} || POST /x {…}` is if-then-else. Errors abort exactly as with `&&` — `||` never catches a 401 or a timeout.
- **`>> file` appends** instead of overwriting, merging by content. JSON merges into a single array as a textual splice — `"a"` then `"b"` gives `["a","b"]`; arrays concatenate, single values are wrapped/pushed — without re-serializing existing bytes, so formatting like `1e2` survives. `.ndjson` targets get JSON-array payloads exploded to one compact object per line; `.csv` appends drop the payload's duplicate header row; anything non-JSON text-appends. The first write to a missing or empty file is identical to `>`. `>> clipboard` is rejected. Tab completion works after `>>`, and the recalled input line keeps the `>>` so a re-send stays an append.
- **The default request timeout is now 10 minutes** (previously reqwest's hidden 30s default applied), and hitting it says so: `Timed out after 600s — raise it with --timeout <seconds> (0 = no timeout)` instead of the misleading "Is COS running?", which now appears only for genuine connection failures. `--timeout 0` disables the timeout entirely.
- **The loading spinner reports the step that's actually running**: `Loading connection X from 1P…` → `Connecting to X…` → `Loading API spec from X…`, instead of blaming 1Password for the whole wait. 1Password CLI calls are bounded at 30s with an actionable message (`Is op signed in? Try: op signin`) and surface `op`'s own stderr on failure; previously a wedged `op` hung the client forever with its errors swallowed. Also fixed the missing-`op` check, which could never trigger.
- **Chain-aware editing**: GET→PUT body auto-promotion — plus its revert and the array `[` wrap — applies only to the last `&&`/`||` segment. Typing ` && ` after a GET no longer turns it into a PUT, and deleting a promoted trailing segment can never revert an explicitly typed method elsewhere on the line. Tab completion and ghost text work per segment (outfile completion mid-chain, URI completion in the last segment), and completing a path in an earlier segment preserves the rest of the chain. The input area keeps the full chain visible while it executes instead of flashing individual segments.
- Fixed the `@file`-error path dropping ` > outfile` from the restored input line.
